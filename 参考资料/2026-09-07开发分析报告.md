## 二、关键点分析

### 1. 时间线模块（16:03–17:25，4 版迭代）
| 版本 | 解决的核心问题 |
|---|---|
| v1 | 从无到有：按文件真实修改时间分层 + 类型筛选 + 日期折叠 |
| v2 | 视觉重做：贯穿全页实色竖线、圆点/箭头与线 X 对齐、筛选行冻结 |
| v3 | 布局重构：日期行单独一行 + 卡片列表；修复滚动后时间线消失 |
| v4 | 收尾：全部折叠/展开按钮、标签筛选、紧凑行高 |

**经验**：像素级对齐（圆点/箭头/竖线三点 X 零偏差）通过 `box-sizing` 统一解决；"滚动后下方消失"根因是 flex 限高，改内容高度贯穿。

### 2. 报表中心（17:25）
- 日报 / 周报 / 月报 / 季报 / 年报**自动生成**（概览 / 趋势 / 热门标签 / 新增明细）
- 可编辑、导出 .md / .html、保存回知识库（resources type=report + reports 表）
- 数据全部来自本地 SQLite 现算，无硬编码

### 3. 思维导图引擎选型（今日最重要的决策）
- **过程**：自研 ECharts tree → 自由坐标算法 → 组织图，三次被用户截图否决（节点错乱、XY 方向不对）
- **决策**：20:20 切换 **simple-mind-map v0.14.0-fix.3**（MIT 开源，组织图/概要/边界/关联线/多选拖拽内置），一次性解决布局算法问题
- **验证**：五布局、四主题、概要、边界、关联线、颜色形状全量真机通过
- **教训**：复杂图形交互组件（布局算法、连线、编辑）应**优先选成熟引擎**，自研成本远超预期；引擎替换后 8 个真机 bug 逐一修复即达可用

### 4. 交互攻坚（21:24–22:41，两个提交）
- **概要多行压行**（最难）：SMM `handleDataToRichText` 在 `isOldRichTextVersion=true` 时无条件归一化，纯文本 `\n` 被 htmlEscape 吞掉 → 三版映射（纯文本 / 单 `<p>`+`\n` / 多 `<p>`）最后一版成功；DB 用 `\n` 存储、载入拆多 `<p>`
- **关系线点选**：SMM 点击热区是透明描边 path，SVG 默认 `pointer-events` 不命中透明描边 → CSS `pointer-events: stroke` + 线文字 `pointer-events: none`
- **边界语义**：否决 SMM 原生 outerFrame（每个节点各挂一个矩形），自定义 khBounds 整体矩形（选中组外围包裹）

### 5. 6 点 UI 优化 + 主题背景 bug（23:06–23:10）
- 主题跟随系统深浅色：`html.dark` MutationObserver 联动 + 各主题 darkBg
- 节点统一圆角 10（SMM 默认层级 borderRadius=5 需 root/second/node/generalization 逐层覆盖）
- **bug 根因**：SMM 重渲染用 `themeConfig.backgroundColor`（**不是 `background`**）覆盖容器背景 → 四套主题补双字段

## 四、踩坑与教训（工程资产）

| # | 坑 | 根因 | 解法（已沉淀进文档） |
|---|---|---|---|
| 1 | 自研导图布局错乱 | 布局算法（组织图/自由坐标）复杂度被低估 | 换成熟引擎 simple-mind-map |
| 2 | 概要多行压成单行 | SMM 富文本归一化吞 `\n` | 数据用多 `<p>` 段；DB 存 `\n` 转换 |
| 3 | 关系线点不中 | 透明描边 path 不触发 pointer-events | CSS `pointer-events: stroke` |
| 4 | 切布局背景变白 | SMM 用 `backgroundColor` 字段（非 `background`）覆盖容器 | 主题双字段 + 深色一并替换 |
| 5 | 节点圆角不一致 | SMM 默认主题层级各带 borderRadius=5 | root/second/node/generalization 逐层写 10 |
| 6 | 测试数据污染 DB | `mm.setData()` 直接覆盖真实导图（29 节点） | 测试前备份 DB / 只读验证；已重建干净测试导图 |
| 7 | 空 `<g>` 层崩溃 | 无边界时空 kh-bound-layer 让 SMM Scrollbar rbox() 崩溃 | 无边界时必须移除空 `<g>` |
