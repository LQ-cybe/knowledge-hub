## 2026-09-10（第 26 轮迭代：鱼骨图斜线贴合节点轮廓 + 选中高亮框贴合节点形状 + 预打包依赖定性 + 节点间距校准）

**本轮的起点是三个"看起来不相干"的现象，最终收敛为两类根因：SMM 主题参数语义 + 前端预打包缓存。**

**① 鱼骨图斜线"断开"（Task 33）**
- 现象：二级节点下方的斜线没连到节点，肉眼可见一段缝。
- 根因：斜线端点画在**节点矩形包围盒的角点** `(item.left, item.top+item.height)`，但节点是**圆角矩形**（所有主题 `borderRadius=10`），角点在圆角轮廓**外侧**、沿对角线偏离 `r×(√2−1) ≈ 4.14`——几何必然，不是"差一点"。
- 修复 `web/smm-patches/Fishbone.js` 新增 `reachNodeOutline()`：从角点沿连线方向以 0.2 步进，用「点到内部收缩矩形距离 ≤ r」判定进入节点，取首个进入点再向内压 2（节点绘制在连线之上，压进的一段被填充色遮住）。
- 验证：8 条斜线端点 SDF = −0.8 ~ −1.3（负值 = 已在节点内部）。

**② 节点选中/悬停高亮框贴合节点自身形状**
- 现象：选中节点时外框比节点大一圈、圆角也对不上（`.smm-hover-node`，尺寸 = 节点 + `hoverRectPadding×2`，圆角固定 `hoverRectRadius=5`）。
- 修复（只动 `web/src/MindmapView.vue`）：`new MindMap({ ..., hoverRectPadding: 0 })` + `themeCfgFor` 里把 `hoverRectRadius` **逐层**写进 `root/second/node/generalization`。
- **关键坑**：SMM 用 `deepmerge(内置主题, opt.themeConfig)` 构建 themeConfig，内置主题**每层**都带 `hoverRectRadius: 5` → 只写最外层会被层级值盖掉（首次实测 rx 仍为 5）。
- 验证：选中后 `.smm-hover-node` `x=0,y=0,w=64,h=35,rx=10`，与 `.smm-node-shape` 只差 0.9px（=描边半宽）。

**③ "重叠又回来了"的定性 = 旧预打包依赖（不是代码回退）**
- 现象：用户截图里长节点（530×74）把右侧三个分支的子节点全罩住。
- 定性方法（**从截图反推代码版本**）：对截图做填充色连通域分析（`abs(rgb-target).sum()<14`）定出每个节点框，用已知节点标定缩放系数 = 2.0；量得第一层相邻间距 **105/121/120.5 = 节点自身宽度 + marginX(10.5)**，正是**官方原版公式** `topTotalLeft += item.width + marginX`；当前补丁版实测为 **588 = 子树宽度 + marginX** → 结论是**页面持有旧的预打包依赖**。
- 根因（两条环境因素叠加）：`start-hidden.vbs` 原本**无条件**启动前后端，端口被占时 Vite 静默递增到 5179/5180，**多实例共享 `web/node_modules/.vite/deps` 互相覆盖预打包缓存**；叠加老标签页长期不重载。
- 处置：`start-hidden.vbs` 改**幂等**（`netstat | findstr LISTENING` 探测 5177/5178，只启动未监听的；保持纯 ASCII + CRLF）；`web/vite.config.ts` 加 `server.strictPort: true`（占用直接失败，不再递增）；清游离实例 + 删 `.vite` + 重启单一实例。
- **❌ 实测否决的两个方案**：`optimizeDeps.force: true`（Vite 启动要批量删 `.vite/deps` 73 条，被 WorkBuddy 注入的 `node-safe-delete-shim.cjs` 拦截 → 启动失败）；`optimizeDeps.exclude: ['simple-mind-map']`（SMM 有 `eventemitter3` 等 CJS 依赖，排除后浏览器报 `does not provide an export named 'default'`，页面白屏）。**结论：SMM 必须走预打包，改补丁后仍要"删 .vite + 重启"**。

**④ 节点间距校准**
- 现象：子节点之间纵向间距被"完全消掉"（两节点直接挨着）；同时向右/向左/思维导图三个布局的**分支纵向距离过大**。
- 根因：SMM 实际间距 = `marginY + hoverRectPadding×2`，**内置默认 `node.marginY = 0`**——子节点本来贴死，一直靠 `hoverRectPadding: 2` 的 4px 撑着；本轮为去掉选中包围盒把它设为 0，这 4px 也一起没了。
- 修复（只动 `themeCfgFor`）：`cfg.node.marginY = 10`（**所有布局**；组织图横向布点，其「兄弟间距」恰好读 `marginY`，同一数值正好给它 10px 横向间隙）；`cfg.second.marginY = 10`（仅 `right/left/mind`，内置 40 → 10）。
- A/B 实测（六顶思考帽·向右布局·第 2 层相邻间隙，单位 px）：`40` → 60.5/59.5/78/78/78/98.5（总高 750）；`20` → 40.5/39.5/58/58/58/78.5（630）；**`10` → 30.5/29.5/48/48/48/68.5（570）**。前两条正好 −50%；带 3 子节点的分支只能 −30%（子树撑开量是防重叠刚性下限）。
- 回归：5 张导图 × 8 种布局，两两重叠 0、子节点纵向最小间隙 10；`vite build` 2714 modules 零错误。

**改动文件**：`web/smm-patches/Fishbone.js`、`web/src/MindmapView.vue`、`web/vite.config.ts`、`start-hidden.vbs`（其余为本轮前半所见下方第 25 轮条目）。

### —— ① MD 编辑器：使用编辑功能时光标跳到文档末尾（根因级修复）

- **问题**：在 MD 编辑窗口点工具栏按钮（加粗/斜体/标题/列表等）或按 Ctrl/⌘+B/I/K，光标总会跳到整篇文档末尾，且左边编辑、右边预览"不同步"。
- **根因**：`surround/prefixLines/insertBlock` 先改 `content.value`（v-model 绑定），Vue 重渲染把 `<textarea>` 的 caret 重置到末尾，再在 `nextTick` 里恢复选区——该时序在原生 roam/重渲染同帧竞争中失效，光标落到末尾；编辑器滚到末尾又带动预览滚到末尾，表现为"左右不同步"。
- **修复（DOM-first）**：三个函数改为**先直接操作 DOM**——`ta.value = newVal; ta.setSelectionRange(ns, ne); content.value = newVal; ta.focus()`。因 `ta.value` 已等于新值，Vue patch 判定无变化、**不触碰 textarea**，光标得以保留。去掉了 `nextTick` 依赖。
- 实测：文档中段选中"中间"→点「加粗」，`selectionStart` 17→19（正确落在 `**中间**` 内），`cursorJumpedToEnd=false`，值变为 `…**中间**…`。
