# Knowledge Hub 本地知识库 — 功能说明文档

> 版本：v0.6（2026-09-07）
> 项目位置：`D:\编程开发\开源项目\knowledge-hub`
> 技术栈：本地 Web 架构（Vue3 + Element Plus / Node.js + TypeScript / SQLite + FTS5），纯本地运行，无云端依赖。

---

## 一、整体架构

软件分为**两层 + 一个入口**：

```
┌─────────────────────────────────────────────┐
│  渲染层（前端 web/，Vite :5178）            │
│  工作台 · 浏览 · 图谱 · 时间线 · 报表        │
│  Element Plus 组件 + ECharts 图表            │
└──────────────────┬──────────────────────────┘
                   │ HTTP /api（axios 代理）
┌──────────────────▼──────────────────────────┐
│  业务层（后端 server/，Node :5177）          │
│  路由 routes/：resources · reports           │
│  规则：扫描、打标、搜索、报表周期计算        │
└──────────────────┬──────────────────────────┘
                   │ better-sqlite3
┌──────────────────▼──────────────────────────┐
│  数据层（SQLite knowledge.db）              │
│  resources / tags / resource_tags /         │
│  note_links / reports / attachments         │
│  + FTS5 全文索引（三触发器同步）            │
└─────────────────────────────────────────────┘
```

- **数据层**：所有实体（文件、文件夹、笔记、书签、待办、标签、报表）统一入库，每个资源带唯一 `id`（UUID）；标签通过 `resource_tags` 关联表多对多映射，与磁盘文件内容零耦合。
- **业务层**：保存/修改规则 + 界面操作执行规则（如"打标可递归到子文件"、"报表周期计算"、"搜索排序策略"）。
- **渲染层**：只负责取数、布局、交互与图表展示，不持有业务状态。

> 通用结论：任何软件都可抽象为"数据层 + 业务规则 + 渲染层"三层；本项目的价值在于把文件系统镜像成结构化数据库，再提供多维展示与批量操作。

## 二、数据表结构（SQLite）

| 表 | 用途 | 关键字段 |
|---|---|---|
| `resources` | 统一资源表（文件/文件夹/笔记/书签/待办/报表） | `id, type, title, path, parent_id, content, size, done, created_at, updated_at, status` |
| `tags` | 标签定义 | `id, name, color` |
| `resource_tags` | 资源↔标签多对多 | `resource_id, tag_id` |
| `note_links` | 笔记双链（引用维度，M5 后用） | `source_id, target_id` |
| `reports` | 已保存报表 | `id, title, type, content_md, content_html, period_start, period_end, created_at` |
| `attachments` | 附件 | 预留 |
| `resources_fts` | FTS5 全文索引（虚拟表） | `title, content`，由 `resources_ai/ad/au` 三个触发器在插入/删除/更新时自动同步 |

**关键设计**：文件/文件夹是磁盘扫描的镜像（`scanner` 增量扫描），**标签是独立于磁盘的本地元数据**——标签状态丢失不影响文件内容，重扫/改名均不触碰标签（仅需在扫描时保留 id 映射）。

## 三、核心功能模块

### 1. 工作台
- 顶部统计：资源总数 / 文件数 / 文件夹数（类型分布）
- 常用标签卡片（按使用次数 TOP10，点击跳转浏览页按该标签过滤）
- 顶层目录卡片（文件数/子目录数/占用空间）
- 最近更新文件列表

### 2. 浏览（= 原"浏览 + 数据库"合并页）
- 左侧**文件结构树**：Code 主目录下逐级目录树；默认全部折叠；支持全部展开/全部折叠；行高 21px
- 右侧**表格 / 卡片**双视图切换：
  - 表格：类型 / 标题 / 路径 / 标签 / 大小 / 更新时间，行高 29px，标签统一**主色蓝底白字**
  - 卡片：缩略图（图片类文件预览）/ 图标 + 标题 + 元信息 + 标签
- 筛选：标题/路径关键字、类型、标签、更新时间排序；**全文搜索（FTS5）**
- **打标**：单文件/批量打标（可勾选"同时应用到所有子文件和子文件夹"递归）；弹窗内可直接新建标签
- 分页：共 N 条 / 每页 N 条 / 前往第 N 页（全中文）

### 3. 图谱
- **三维度**：文件夹 / 标签 / 引用（双链，M5 后可用）
- **四视图**：
  - **关系图**：力导向布局，可拖拽，动画已关闭
  - **桑基图**：层级流向
  - **树图**：纵向层级树
  - **思维导图**：横向布局（根在左），节点按文件夹/文件着色，**点击节点折叠/展开，双击节点弹出打标对话框（即编辑）**
- **层级控制（所有视图通用）**：全部展开 / 全部折叠 / 折叠到第 N 层
  - 层数语义：**第 1 层 = 全部折叠（根 + 一级节点）**；第 N 层 = 显示到第 N 级；上限 = 树层级数 - 1
  - 实现：树图/思维导图用数据剪枝（`pruneTree`）+ 全展开，规避 ECharts `initialTreeDepth` 的层数偏移 bug；多根森林包一层隐藏虚拟根 `__forest__`
- **主题**：图表颜色随系统深色/浅色自动切换（监听 `kh-theme-change` 事件重渲染）

### 4. 时间线（垂直时间线）
- 按创建时间倒序分组（每天一组），左侧贯穿时间线 + 圆点 + 箭头
- 每条显示：名称 / 标签 / 时间或大小
- **筛选**：类型下拉 + **标签下拉**（含使用次数，`Access（163）` 格式），可清空
- **折叠**：每天一组可单独折叠（持久化到 sessionStorage）；顶部「全部折叠 / 全部展开」按钮（带边框方格样式，紧跟筛选）
- 行高紧凑；筛选行固定在页面顶部

### 5. 报表中心
- 五类周期：日报 / 周报 / 月报 / 季报 / 年报（按资源 `created_at` 落入统计区间计算）
- 报表内容：周期内新增资源明细 + 热门标签排行 + 类型分布
- 可编辑（Markdown）、导出（.md / .html）、保存（写入 `resources` type='report' + `reports` 表）
- 右侧已保存报表列表

### 6. 思维导图（独立导图工作区，参考 NexaNote 织记）
- **引擎**：**simple-mind-map v0.14.0-fix.3**（国产 MIT 开源引擎，已 `npm install`；组织图/概要/边界/关联线/节点样式/多选拖拽全部内置）。此前自研布局（ECharts tree / 自由坐标算法）被用户多次否决，最终切换到成熟引擎。NexaNote-main 源码（Flutter+FastAPI 手写笔记应用）经核查无思维导图代码，不可移植。
- **导图库**：多张导图管理（新建/打开/删除，显示节点数与更新时间）
- **编辑器**（三栏布局，对齐 NexaNote 界面）：
  - 顶部工具栏：＋子主题 / ＋同级 / 概要 / 边界 / 关系 / 缩放（40%~200%）/ 已保存状态
  - 左侧布局面板：**自由编辑 / 向右 / 向左 / 组织图 / 放射**（快捷键与多选等操作提示已移入本文档「八、思维导图交互说明」，界面不再显示文字提示）
  - 右侧节点属性：**文档主题**（Nexa 明亮 / Nexa 深色 / 经典分支 / 音蓝架构）、节点颜色（6 色覆盖，写 `data.fillColor`）、节点形状（自动/矩形/圆角/椭圆，写 `data.shape`）
- **编辑能力**：单击选中（右侧面板联动）、双击改名、Enter 同级、Tab 子级、Delete 级联删除、自由布局拖拽、概要（`ADD_GENERALIZATION`，数据 `data.generalization`）、边界（自定义整体矩形，见下）、关联线（`ADD_ASSOCIATIVE_LINE`，数据为 `data.associativeLineTargets` **uid 字符串数组**）
- **多选才可用的三按钮**：工具栏「概要 / 边界 / 关系」必须**选中 ≥2 个节点**才可点击（单选时置灰禁用），通过 Shift 多选或按住选择实现；"选中 2 个节点"是三者共同的交互前提
- **概要（多行直接编辑）**：点「概要」按钮后**不弹窗**，直接在节点内进入可编辑文本框（contenteditable），可输入**多行文本**；回车换行、失焦/回车提交并自动保存
  - 多行实现要点：概要文本在 SMM 数据中必须是**多个 `<p>` 段**（`<p>行1</p><p>行2</p>`），纯文本 `\n` 会被 SMM `htmlEscape` 吞掉换行；DB 存储用 `\n` 分隔（`</p>`→`\n` 转换），载入时按 `\n` 拆成多 `<p>`
- **边界（整体矩形语义，已否决 SMM 原生 outerFrame）**：多选 ≥2 个节点后点「边界」，在**这些节点的外围创建一个整体虚线矩形**包裹（不是给每个节点单独挂框）；矩形可单击选中（红边高亮）、**双击文字改名**、Delete 删除；矩形与节点同层，位于节点之下不遮挡内容
- **关系线（底层可点选）**：多选 ≥2 个节点后点「关系」创建（选中顺序即方向，先选为起点）；线绘制在**节点底层**（`associativeLineIsAlwaysAboveNode: false`，不盖节点内容）；**单击线可选中**（高亮变蓝）、**双击线中文字可内联编辑**（出现白底输入框）、Delete 删除
  - 可点选实现要点：SMM 的点击热区是**透明描边 path**，SVG 默认 `pointer-events` 不命中透明描边，需 CSS 强制 `.smm-associative-line-container path { pointer-events: stroke }`，且线文字 `pointer-events: none` 穿透到热区
- **自动保存**：`data_change`/`view_data_change` → 600ms 防抖 → 全量保存（nodes/links/members 四请求并行；服务器端 members 先删本图组员+清理孤儿组员再插）
- **数据模型**：`mindmaps`（导图，layout 存 free/right/left/org/radial）+ `mindmap_nodes`（节点，kind=node/boundary/summary，含颜色/形状）+ `mindmap_links`（关系连线 source→target）+ `mindmap_members`（边界/概要组员 group_id→node_id）
- **关键映射细节**（SMM 字段权威，勿凭记忆）：
  - SMM Node 实例：`node.getData('text'|'uid'|'fillColor'|'shape')`；`node.nodeData.data` 为数据体；虚拟根 `__VR__` 判断用 uid
  - 概要：DB summary（kind=summary, parent=所属节点）→ 载入挂 `data.generalization=[{text:'<p>…</p><p>…</p>', richText:true}]`；保存读 `data.generalization`，多 `<p>` 转 `\n`
  - 边界：**自定义 khBounds 运行时层**（DB boundary + members 构建，不向 SMM data 挂 outerFrame）；渲染时在 `.smm-container` svg 内插 `g.kh-bound-layer`（首个子元素、节点之下），用 `node.getRect()` 取成员包围盒 + padding 14 画虚线矩形 + 左上角名称文字；无边界时**必须移除空 `<g>`**（空 g 会让 SMM Scrollbar `rbox()` 崩溃致整图空白）；单击矩形选中、双击文字改名、Delete 删除，smmToDb 时写回 nodes(boundary 行)+members
  - 关联线：`data.associativeLineTargets` 是 **uid 字符串数组**（非对象数组）；节点激活事件为 `node_active`（v0.14 无 `node_click`）；`INSERT_CHILD_NODE(openEdit, [node])` 首参是 openEdit 布尔；激活的线通过 `clickPath` 变蓝显示（无 class 标记）
  - 旧 DB 数据 title 为双重转义 HTML（`&lt;p&gt;111&lt;/p&gt;`），载入过 `plain()` 解码剥离标签
- **图谱页与导图页分离**：图谱页（关系图/桑基图/树图）**不再包含思维导图入口**；思维导图仅在顶部「导图」页使用

## 四、搜索原理（重点）

### 1. 索引层：SQLite FTS5
- 建表 `resources_fts(title, content)`，tokenizer 为 `unicode61`（英文按词切分、中文按**单字**切分）
- 三个触发器自动同步：
  - `resources_ai`（INSERT 后）：新资源写入索引
  - `resources_ad`（DELETE 后）：删除索引条目
  - `resources_au`（UPDATE 后）：先删旧再插新（**改名/改内容后搜索立即生效**）

### 2. 查询层：双路合并
```
路径 A（全文命中）：resources_fts MATCH '"关键词"*'
  └── JOIN resources 取元数据，snippet() 生成高亮片段
路径 B（标题/路径 LIKE 兜底）：title LIKE %词% OR path LIKE %词%
  └── 排除已在路径 A 命中的 id（去重）
```
- `MATCH '"q"*'`：前缀匹配（"错误"可命中"错误处理"）
- 中文限制：unicode61 单字切分下，**只保证 1-2 个字的短语匹配**；更长关键词需后续接入中文分词器（M2 优化项）

### 3. 排序策略
```
ORDER BY
  type 优先级：file > note > bookmark > todo > report > folder
  （文件结果优先，文件夹排最后——避免搜"错误"出现大量无关文件夹）
  → 标题精确命中（title LIKE）优先于内容命中
  → created_at 倒序
LIMIT 100
```

### 4. 前端错误处理（已修复的 bug）
- 症状：搜索"错误"曾显示 1170 条全量无关结果
- 根因：`onSearch` 的 `try/finally` **缺少 catch**——请求异常时静默保留上一列表（未搜索状态的全量数据）
- 修复：catch 中弹出「搜索失败」错误提示，不再误导为搜索结果

## 八、思维导图交互说明（帮助信息）

> 引擎：simple-mind-map v0.14.0-fix.3（MIT 开源）。导图数据存于 mindmaps / mindmap_nodes / mindmap_links / mindmap_members 四表。

### 1. 基本操作
| 操作 | 方式 | 说明 |
|---|---|---|
| 选中节点 | 单击 | 单击选中单个节点 |
| 多选节点 | Shift + 单击 | 可同时选中多个节点（用于概要/边界） |
| 编辑文字 | 双击节点 | 进入文字编辑 |
| 新建同级 | Enter | 在选中节点下方连续创建同级节点（可直接输入文字） |
| 新建子级 | Tab | 为选中节点创建子节点 |
| 删除节点 | Delete | 删除选中节点（含子树） |
| 调整层级 | 拖拽节点 | 拖到目标节点上方/下方/内部改变层级 |
| 全部修改 | 自动保存 | 操作后约 0.6 秒自动写入本地数据库 |

### 2. 关系线（两点间联系）
- **操作**：单击起点节点 → 点工具栏「关系」→ 再单击目标节点（**支持跨层级**，两个节点可以是任意层级）
- **语义**：在两节点之间建立一条**直线联系**，用于表达跨分支的关联（如"同步一致"）
- **样式**：细线（1.5px）+ 主题色虚线；**渲染在节点下层**，不会遮挡节点内容
- **文字**：双击关系线可编辑连线文字（如"同步一致"）

### 3. 概要（共同属性说明）
- **操作**：按住 Shift 选中**同一父节点的多个子节点** → 点工具栏「概要」→ 弹出多行输入框
- **语义**：概要显示在所选节点组上方，是描述这组节点**共同属性**的**长文本**（支持多行，如功能说明、规则描述）
- **约束**：只能针对同一父节点的多个子节点；已有概要的节点组不可重复添加

### 4. 边界（矩形分组）
- **操作**：选中一个父节点 → 点「边界」→ 输入边界名称 → **以矩形框包裹其所有子节点**；也可 Shift 多选同级节点框住所选
- **语义**：矩形显示在**底层**，用于把一组节点圈成功能分区（如"产品计划"下的功能/数据/界面）
- **文字**：双击边界文字可修改名称

### 5. 主题与配色
- 四套主题：Nexa 明亮 / Nexa 深色 / 经典分支 / 音蓝架构（右侧属性面板切换，随导图保存）
- **节点外观统一**：所有节点（根/二级/分支/概要）统一**圆角矩形**（圆角 10px），二级及以下节点**无边框实心块**，与父节点同款方格；层级差异仅体现在配色深浅

### 6. 放射（鱼骨）布局 ——「子树紧凑拼接」算法（重要）

**需求背景**：旧鱼骨布局按固定角度（fishboneDeg）推算横向位置，分支多时主干被拉得很长、兄弟之间出现大量空白；且折叠某分支后兄弟节点会「跳位」（第 3 轮曾用 expandedWidthCache 占位修复，但角度方案本身仍有空白浪费）。用户否决「继续调角度」的路线，明确要求：**下一节点位置 = 上一节点（子树最长文字 + 留白）**。

**算法（基于 simple-mind-map 源码补丁，`web\smm-patches\Fishbone.js` 与 `fishboneUtils.js`）**：

- **二级节点**：分「上方 / 下方」两行（鱼骨形态），起点对齐根节点右侧；布局分两步：
  1. 初排：按自身宽度 + 留白横向排开；
  2. 精排（`adjustLeftTopValueAfter`）：按**子树最大水平宽度 + 10px 留白**逐兄弟推进——`width = getNodeBoundaries(item).right - left`，下一个兄弟 `left = 上一个兄弟的 left + 子树宽 + 10`。这就是「每个节点最长文字 + 留白 = 下一个节点位置」。
- **折叠占位**：折叠节点无子节点实例，用 `expandedWidthCache`（节点 uid → 最近一次展开时的子树宽度）占位，兄弟位置不受折叠影响（不跳位）。
- **三级及以下**：统一排在该父节点右侧 `父宽 + 10px` 处（替代原 `fishboneDeg` 角度公式），每层递进，横向紧凑；纵向仍按 getNodeAreaHeight 累计，保持鱼骨「上下翻转」的层级关系。
- **连线（renderLine）**：改为**父节点中心 → 子节点中心**直连（根节点为「主干水平线 + 到各二级节点中心斜线」）；每段线自行创建 path 对象（`this.lineDraw.path()` + `node.style.line(line)` + `node._lines.push(line)`），**不再依赖渲染器传入的 lines 数组**（原实现 `lines[index]` 在列式直连时会取到 undefined 而崩溃）。
- **总宽**：横向总宽 ≈ Σ（各二级子树宽 + 留白），一屏完整收纳；不再随分支数量无限拉长。

**补丁警告**：该算法改动 `simple-mind-map` 的 `src/layouts/Fishbone.js` 与 `src/layouts/fishboneUtils.js`（node_modules 内，npm install 后需按 `web\smm-patches\README.md` 恢复）。
