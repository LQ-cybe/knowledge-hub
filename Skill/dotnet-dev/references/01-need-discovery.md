# 需求引导与用户沟通

这个文档面向零基础用户的 .NET 需求澄清与沟通方式。后续 AI 在正式编码前，优先先做这一轮。

## 核心目标

不是让用户讲技术方案，而是帮助用户讲清楚：

- 现在怎么手工做
- 最痛的是哪一步
- 最终想看到什么结果
- 给谁用
- 用几次
- 需要窗口、按钮还是自动处理
- 是否需要发给别人使用
- 是否需要做成 `exe`
- 是否需要兼容 `Win7`
- 目标人群用什么 Windows 版本（`Win7` / `Win10` / `Win11`），这影响 .NET 版本选择
- 当前项目优先用较低版本先发布是否可行，例如先评估 `net6.0`，不够再升 `net8.0`
- 如果准备做框架依赖发布，是否希望保留向上兼容能力（`RollForward`）
- 如果要交付成品，更希望 `源码交付`、`框架依赖发布`、`自包含单文件发布`，还是 `自包含目录发布`
- 更适合做成批处理、桌面工具还是可分发成品

## 沟通原则

- 先说结果，再说动作
- 优先用生活化表达，不堆技术术语
- 需要用户授权时，说清楚"为什么要执行"和"执行后会发生什么"
- 出现报错时，先给用户结论，再自己排查，不把分析责任丢给用户

### 推荐表达

- 不说"请你在终端执行命令"，优先说"我来帮你执行，必要时你点允许即可"
- 不说"这是 NuGet 依赖问题"，优先说"缺少程序运行需要的组件，我来补上"
- 不说"请配置环境变量"，优先说"我会把配置文件准备好，你后面只需要改这几个值"
- 不说"打包成二进制"，优先说"我会帮你做成可以双击运行的 exe"

## 首轮建议话术

> 你先别急着说技术名词，直接按你现在的真实操作流程描述就行。你现在是先打开什么文件、访问什么网页、复制什么内容，最后希望看到什么结果？
> 另外，这个工具是你自己偶尔用，还是要发给别人长期用？最终用户的电脑用的是 `Windows 7`、`Windows 10` 还是 `Windows 11`？你更希望它是点一下就跑，还是打开一个窗口再点按钮？如果要发给别人，是希望只给源码，还是给能直接运行的发布包？

## 必问问题

1. 你现在是手工怎么做这件事的？
2. 最费时间的是哪一步？
3. 你希望最后得到什么结果？
4. 这是你自己用，还是别人也要用？
5. 你希望怎么触发？双击运行、点按钮、定时执行，还是手动选择文件？
6. 你能接受命令行窗口吗？如果不接受，优先做成窗口工具。
7. 最终用户的电脑里是否需要兼容 `Windows 7`？
8. 如果不需要 Win7，目标用户的电脑主要是 `Windows 10` 还是 `Windows 11`？（注：部分 Win10 不支持 .NET 10，含 Win10 用户时优先推荐 .NET 8）
9. 当前功能如果先按 `net6.0` 做，你能接受吗？如果不够，我再评估升到 `net8.0`；只有明确需要时才考虑 `net10.0`。
10. 如果要做框架依赖发布，你更希望“锁定目标运行时”，还是“允许向上兼容到更高已安装运行时”？如果不懂区别，我先解释。
11. 如果要交付成品，你更偏向哪种方式：`源码交付`、`框架依赖发布`、`自包含单文件发布`，还是 `自包含目录发布`？如果不懂区别，我先解释给你。
12. 你能不能给我样例文件、截图、网页链接或报错信息？
13. 这次是从零开始，还是已有代码/旧工具要改？
14. 数据里有没有账号、密码、Cookie、客户信息等敏感内容？
