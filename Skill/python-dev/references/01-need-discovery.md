# 需求引导

这个文档面向零基础用户的 Python 需求澄清。后续 AI 在正式编码前，优先先做这一轮。

## 核心目标

不是让用户讲技术方案，而是帮助用户讲清楚：

- 现在怎么手工做
- 最痛的是哪一步
- 最终想看到什么结果
- 给谁用
- 用几次
- 需要窗口、按钮还是自动处理
- 是否需要发给别人使用
- 是否需要做成 `exe`
- 更适合做成脚本、桌面工具还是可分发成品

## 首轮建议话术

> 你先别急着说技术名词，直接按你现在的真实操作流程描述就行。你现在是先打开什么文件、访问什么网页、复制什么内容，最后希望看到什么结果？
> 另外，这个工具是你自己偶尔用，还是要发给别人长期用？你更希望它是点一下就跑，还是打开一个窗口再点按钮？
> 你把“从开始到结束”说一遍，我来帮你判断更适合做成哪种 Python 工具。

## 必问问题

1. 你现在是手工怎么做这件事的？
2. 最费时间的是哪一步？
3. 你希望最后得到什么结果？是新文件、Excel、图片、邮件，还是屏幕上的提示？
4. 这是你自己用，还是别人也要用？
5. 你希望怎么触发？双击运行、点按钮、定时执行，还是手动选择文件？
6. 你能接受命令行窗口吗？如果不接受，优先做成窗口工具。
7. 别人的电脑上是否已经装了 Python？如果不确定，优先考虑 `exe`。
8. 你能不能给我样例文件、截图、网页链接或报错信息？
9. 这次是从零开始，还是已有代码/旧工具要改？
10. 数据里有没有账号、密码、Cookie、客户信息等敏感内容？
11. 如果涉及网页自动操作，你电脑上有没有 Chrome、Edge 或其他 Chromium 内核浏览器？
12. 如果要用浏览器自动化，你更希望复用本机浏览器，还是需要我帮你定位浏览器路径？

## 必要素材要求

- 文件处理类：至少提供 1 份输入样例和期望输出样例
- 网页抓取类：提供网页链接、登录要求、需要抓取的字段
- 浏览器自动化类：补充本机浏览器情况、是否已有 Chrome/Edge、是否接受 AI 帮忙查浏览器路径
- 桌面界面类：提供界面草图、按钮说明或参考截图
- 报错排查类：提供完整报错文本或截图，不要只说“报错了”

## 场景判断

### 更适合脚本 / 自动化

- 自己用为主
- 触发方式简单
- 没有复杂界面
- 更关注效率，不太在意交互体验

### 更适合桌面工具

- 需要普通用户操作
- 需要文件选择、按钮、输入框、进度提示
- 需要尽量少暴露技术细节

### 更适合可交付成品

- 要发给别人用
- 对方电脑上不一定有 Python
- 希望双击就能运行
- 需要说明文档、示例文件和明确的交付目录

## 需求复述后才能开工

推荐格式：

> 我先确认一下我的理解，你看对不对：
> 1. 你现在是在处理一个……场景
> 2. 输入是……
> 3. 输出要变成……
> 4. 使用方式是……
> 5. 使用对象是……
> 6. 所以我建议做成……，并且由我来帮你运行、测试，必要时再打包成 `exe`
>
> 如果这些都对，我再开始创建项目和写代码。

## 不要急着开工的情况

- 用户只说“帮我做个程序”，但没说输入和输出
- 用户没说清是自己用还是给别人用
- 用户没说清是否需要窗口或 `exe`
- 用户给了现有项目，但还没说清哪些旧行为必须保留
- 用户涉及网站登录、敏感数据、第三方接口，但还没说明权限和风险

## 零基础用户沟通规范

### 核心原则

- 先说结果，再说动作
- 优先用生活化表达，不堆技术名词
- 可以解释术语，但不要默认用户知道术语
- 需要用户授权时，说清楚"为什么要执行"和"执行后会发生什么"
- 出现报错时，先给用户结论，再自己排查，不把分析责任丢给用户

### 推荐表达

- 不说"请你在终端执行命令"，优先说"我来帮你执行，必要时你点允许即可"
- 不说"这是依赖问题"，优先说"缺少程序运行需要的组件，我来补上"
- 不说"请配置环境变量"，优先说"我会把配置文件准备好，你后面只需要改这几个值"
- 不说"打包成二进制"，优先说"我会帮你做成可以双击运行的 exe"

### 执行命令前的话术

> 我准备帮你执行一次环境初始化 / 运行 / 打包。这一步会在你的电脑上创建项目文件或安装所需组件，正常情况下不需要你手动输入命令，只要在弹出授权时点允许即可。

### 报错时的话术

> 这一步没有成功，原因大致是……。我先继续帮你处理，不需要你自己分析终端输出。如果需要你配合，我会明确告诉你只需要做哪一步。

### 交付时的话术

> 我已经帮你把程序跑通过了，并整理好了交付内容。你现在只需要打开……，选择……，再点击……，结果会出现在……。

### 不要这样说

- 不要连续抛出多个库名、框架名、打包器名
- 不要让用户自己阅读长段终端日志
- 不要把"你自己去试试"当作默认交付方式
- 不要只给技术解释，不给用户行动指引
