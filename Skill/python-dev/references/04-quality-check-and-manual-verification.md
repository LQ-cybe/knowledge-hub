# 质量检查与人工验证

生成代码后，后续 AI 不应把“未经运行的代码”直接交给用户。至少要完成自动检查和一次最小人工验证。

## 目标

- 确认代码能运行
- 确认静态检查没有明显问题
- 确认核心功能在样例数据上跑通
- 确认最终用户知道如何验证结果

## 推荐顺序

1. `uv run ruff check . --fix`
2. `uv run mypy .`
3. `uv run pytest -q`
4. `uv run python -m app_name.main` 或入口脚本
5. 如有 GUI，实际启动一次窗口
6. 如有文件输出，检查生成文件是否存在且内容合理

## 自动检查原则

- `ruff` 负责快速发现明显错误和风格问题
- `mypy` 负责提前发现类型不一致
- `pytest` 负责覆盖关键业务逻辑
- 不要求为 GUI 的每个按钮都写测试，但核心逻辑必须可测

## 最小测试集建议

至少准备一组：

- 正常输入
- 空输入或缺失输入
- 边界输入
- 错误输入

## 桌面工具额外检查

- 窗口能否正常打开
- 按钮是否能触发核心动作
- 报错提示是否友好
- 输出路径是否清晰
- 关闭后是否留下用户可找到的产物

## 给用户的验证建议

交付前，后续 AI 应明确告诉用户：

- 现在程序已经跑起来了
- 你可以点哪里、选什么文件、期望看到什么结果
- 如果结果文件已生成，具体在哪个目录

## 不合格交付的典型表现

- 只给代码，没有跑过
- 只说“理论上可以”，没有验证
- 遇到测试失败就让用户自己分析
- 构建了 `exe` 但没确认产物是否真的存在
